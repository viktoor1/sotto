What happens
In
Change who pays
, choosing an organisation loads its members so the user can select the other payer's administrator. If that request fails, the form says:
The transfer service is temporarily unavailable. Try again shortly.
However, the administrator selector contains only its placeholder,
Review payer transfer
is disabled, and there is no retry action. The selected organisation remains unchanged. Users must discover that clearing and reselecting it starts another request, or reload the page.
Reproduction
Verified on main
07f32e5cbdc758ddebfbc8a431302b93d2daa98a
, macOS arm64, Node 24.15.0, Vitest 5.0.0 / happy-dom, using a temporary component probe in a clean checkout:
Render the real
PersonalTransferStart
with synthetic available capabilities, a signed-in account and an organisation
org-b
.
Make the first
fetchMembers("org-b")
reject with
Error("server error (503)")
; configure the next call to return one owner.
Choose
org-b
. Observe the error, the empty administrator selector, the disabled review button and the absence of a retry control. The members API has been called once.
Choose the blank organisation option and then
org-b
again. The owner loads; selecting them enables
Review payer transfer
.
The probe passed against unchanged production code and was removed after verification. It made no quote, transfer or payment request. All APIs were mocked; no live account or native browser journey was exercised.
Expected behaviour
After administrator discovery fails, users can explicitly retry for the currently selected organisation without changing that selection or reloading the page.
Acceptance criteria
A failed members request exposes a clearly labelled retry control for the selected organisation, alongside the existing accessible error.
Retry preserves the selected organisation, clears the previous discovery error while loading and prevents overlapping retry requests. It does not fetch a quote or create a transfer.
A successful retry repopulates eligible administrator choices and removes the recovery control/error. Selecting an administrator enables the existing review flow.
A second failure restores the retry control. A successful empty result is not presented as a request failure.
Changing or clearing the organisation clears recovery state associated with the old selection. Keep member-discovery errors distinct from quote/submission errors so those failures do not offer the wrong retry action.
Add component tests for initial failure, pending retry, repeated failure and recovery using deferred promises and synthetic fixtures; pass the web test suite.
Starting points
PersonalTransferStart
in PayerTransferStart.tsx
:
chooseOrganisation
,
members
, the shared error state and the rendered controls.
PayerTransferJourneys.test.tsx
: existing API mocks and organisation/member fixtures.
Keep this scoped to administrator discovery in the personal transfer-start form. No transfer authority, billing rules, server API or sponsored-transfer changes are needed. Open/closed issues and open PRs were checked for overlap;
#635
covers inbox pagination, not this form.
Suitable for a first contribution using the existing React state and test patterns. Follow
CONTRIBUTING.md
, including DCO sign-off (
git commit -s
).
